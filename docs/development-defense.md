# 开发说明与答辩准备

本文供四位成员阅读源码、复现系统并准备答辩。课序由小组成员共同协作开发，已经实现指导书七项业务功能，采用 Python/Django、React 和 SQLite，在 Windows 本机浏览器运行。以下按 A/B/C/D 四个模块整理实现要点、演示步骤和追问准备，供组员交流与讲解。

## 先运行再阅读

按 README 安装或克隆运行，先使用虚构账号走完学生提交、教师相似检测与批改发布、学生查看反馈、管理员账号和课程管理。演示密码为 DemoPass123!。阅读每个文件时结合页面和对应测试，不背诵未实现的功能。

核心文件与实体见 docs/architecture.md。服务只监听127.0.0.1，SQLite和附件保存在独立数据目录。关闭本机服务窗口才退出服务；数据库、uploads、secret.key需要一起备份。任何用户都不能通过页面访问其他课程或学生原件，限制在服务端执行。

## A 后端主业务

范围：账号与权限、课程、作业、提交版本、批改与成绩。先读 common/permissions.py、accounts/views.py、classroom/views.py、assignments/submissions.py、grading.py、statistics.py 及相应测试。

讲解提纲：系统把管理员、教师、学生的角色权限和课程数据范围同时落实到查询和写入。学生提交的所有权由服务端确定，不能自己指定student_id。提交请求携带UUID；同一编号同一内容返回已有版本，编号相同内容变化返回409，防止响应丢失后多生成一次版本。评分绑定具体Submission，重交不能继承旧分数；教师保存后另行发布，学生只看到已发布结果。

追问准备：为什么不删除旧版本？旧版是批改和复核依据，保留原件及对应成绩。为什么均分不含未提交？未提交和未批改不是实际测得的零分，统计只使用最新已批改记录。SQLite事务不能自动回滚磁盘文件，提交失败还需主动清理本次写入。课程归档和最后管理员保护维护业务关系，而非单纯隐藏按钮。

## B 学生端与基础界面

范围：登录、导航、课程、附件上传、历史版本、成绩反馈、玻璃表单与共享组件。先读 app.tsx、lib/api.ts、features/student、components/glass-dialog.tsx 和 animated-background.tsx。

讲解提纲：前端使用React状态驱动业务页面，数据来自真实接口。登录后CSRF发生旋转，后续写请求读取新token；文件通过XHR显示实际进度。提交失败保留可修改表单，响应丢失时保持request_id。标签筛选由21st.dev收录的Motion Primitives组件实际源码改编，支持方向键、Home/End和减少动态效果偏好；Dialog基于shadcn/ui与Radix，保留焦点约束、Esc和焦点恢复。

追问准备：玻璃效果是什么？半透明背景、backdrop-filter模糊、边框高光和阴影，文字仍保持清晰，不是光学折射模拟。为什么去掉四张统计卡片？以作业列表和截止入口为工作台主信息，把状态数合并到可操作筛选。页面符合桌面演示范围，没有承诺手机体验。

## C 教师和管理员界面

范围：发布编辑作业、分栏批改、成绩统计发布、用户与课程人员维护。先读 features/teacher、features/admin，对照后端对应视图。

讲解提纲：教师按所属课程发布作业，明确截止、满分、必交类别和迟交规则。批改页展示学生列表、当前提交附件和评分表单；成绩页把未交、待批改、待发布与已发布分开。发布和撤回是实际服务端操作，修改成绩后自动撤回发布。管理员维护账号和选课，停用账号后原会话不能继续访问业务。

追问准备：前端按钮隐藏能否代替权限？不能，所有读写接口都按实际角色和课程范围限制。已有提交能否改变满分或改回草稿？不能，避免历史分数口径改变或提交被隐藏；停止提交应关闭作业。导出为何加UTF-8 BOM和转义？便于常见表格软件读中文，并避免姓名或评语被解释成公式。

## D 查重安装和集成验收

范围：文档提取、代码词元、Winnowing、片段复核、Windows打包和验收。先读 plagiarism/extraction.py、normalization.py、fingerprints.py、comparison.py、runner.py，desktop与packaging，再读test_similarity.py和test_runtime.py。

讲解提纲：相同SHA-256还要核对真实字节。报告规范化字符，代码过滤注释与空白词元；不做变量名归一。Winnowing在每个完整窗口选最右最小指纹，双方有效指纹集合分别计算覆盖率，并通过位置映射展示原文。检测只比较不同学生的最新版本，同类报告和同语言代码分别处理，公共模板指纹被排除。教师记录复核，不自动判作弊或扣分。

追问准备：两边覆盖率为什么不同？共同指纹相同，但各自有效集合大小不同。不可检测为何不显示0%？无文字、内容过短或模板排除后不足不能说明没有相似。为什么结果过期？快照记录提交ID和模板修订号，重交或模板变化会改变依据。安装包包含Python运行时和静态资源，通过Waitress启动本机服务；独立数据目录保留SQLite、附件与secret。

## 建议六分钟演示

第一分钟，启动课序，以student01登录，展示课程、作业要求、必交类别和标签筛选。第二分钟，提交报告与代码，刷新后展示新版本和原件下载。第三分钟，切换teacher，对同一作业运行相似检测，筛选代码并查看双方原文片段，记录复核理由。第四分钟，批改最新提交、保存86.50分和评语，在成绩页明确发布。第五分钟，学生查看新成绩，管理员展示用户、角色和课程人员。最后一分钟，关闭服务并重启，确认版本、成绩和复核仍在。

预先用虚构样例建立至少两名学生的同类文件，保留一个未提交学生用于统计解释。若学生在成绩发布后重交，当前版本会重新待批改，演示时应说明版本规则，不误认为分数丢失。

## 高频问题

为什么选Python？一周单机实训需要快速完成文档处理、业务接口和离线指纹；Django提供成熟的认证、ORM和迁移，React负责桌面交互。Java同样可行，但本次已验证Python解析依赖和Windows打包路线。

相似检测如何实现？系统使用本地字符或代码词元处理、Winnowing指纹、公共模板排除和原文位置映射。覆盖率用于提示需要复核的片段，由教师结合上下文判断；人物头像与课程书图已作为本地素材打包，运行时无需外部图片服务。

为什么不用MySQL？单机演示不需要额外数据库服务，SQLite便于安装、备份和交付。面向多班级并发部署时需重新评估数据库与任务队列。

有没有准确率？没有真实标注语料的准确率测试。当前验证覆盖重复文件、注释空白变化、局部片段、模板过滤、版本过期和异常状态；外部论文数据不能作为本系统结果。

重启为什么不会恢复已移除成员或重复生成改名作业？演示内容只在空用户数据库中初始化，完成后保存标记；兼容旧库时尊重已有用户。启动不按可编辑的课程编号和作业标题再次播种。

同时编辑作业和提交会怎样？编辑从读对象开始进入SQLite IMMEDIATE事务，与提交和模板更新按事务顺序处理。已有提交不能再改满分或退回草稿，模板修订号不会被旧编辑实例回写。对应回归在test_review_regressions.py中使用独立SQLite文件和两个线程验证。

最大的边界是什么？没有OCR、变量重命名和语义相似检测，不检索互联网论文库，不监控考试行为；同步检测最多160个附件、400万提取字符。目前尚缺干净Windows电脑完整验收，应在答辩机提前测试。

能否把80%以上直接认定作弊？不能。公共模板、允许合作和共同资料都会产生相似片段，需要结合上下文、来源与学生说明复核。系统只提供线索和记录。

## 每位成员准备到什么程度

每人至少实际完成自己的演示步骤，能够指出两个主要代码文件、一个数据库关系、一个接口校验和一个失败场景。交换角色练习追问；遇到实现边界应明确说明，避免把计划或参考网站效果当成已实现功能。
